# Java 后端面试核心知识

## 一、Java 基础与集合

HashMap 的底层结构是数组 + 链表 + 红黑树。当链表长度超过 8 且数组长度不小于 64 时转为红黑树，退化阈值为 6。
默认初始容量 16，负载因子 0.75，扩容时容量翻倍，并采用高低位拆分避免重新计算哈希。

ArrayList 与 LinkedList 的区别：ArrayList 基于动态数组，随机访问 O(1)，中间插入删除 O(n)；
LinkedList 基于双向链表，头尾操作 O(1)，随机访问 O(n)。实际开发中 ArrayList 使用频率远高于 LinkedList。

## 二、并发编程

线程池的核心参数有七个：核心线程数、最大线程数、空闲存活时间、时间单位、工作队列、线程工厂、拒绝策略。
执行流程是：核心线程未满则创建核心线程；核心线程已满则入队；队列已满则创建非核心线程直到最大线程数；再满则触发拒绝策略。

四种拒绝策略：
- AbortPolicy：直接抛出异常（默认）
- CallerRunsPolicy：由提交任务的线程自己执行，保证任务不丢失
- DiscardPolicy：静默丢弃
- DiscardOldestPolicy：丢弃队列中最旧的任务

线程池大小的经验值：CPU 密集型任务设为 CPU 核数 + 1；IO 密集型任务设为 CPU 核数 × 2 或更大。
更严谨的做法是按任务的等待时间与计算时间之比来估算。

## 三、JVM

JVM 内存区域分为：程序计数器、虚拟机栈、本地方法栈、堆、方法区（元空间）。
堆是垃圾回收的主要区域，分为新生代（Eden + 两个 Survivor）和老年代。
新生代默认比例 8:1:1，对象优先在 Eden 分配，经历一次 Minor GC 后存活的对象进入 Survivor，年龄达到 15 晋升老年代。

常见垃圾回收器：Serial、ParNew、Parallel Scavenge、CMS、G1、ZGC。
CMS 以低停顿为目标，采用标记-清除算法，会产生内存碎片；G1 将堆划分为多个 Region，可预测停顿时间，是当前主流选择。

## 四、MySQL

索引底层是 B+ 树：非叶子节点只存键值，叶子节点存数据并用双向链表连接，因此范围查询效率高。
聚簇索引的叶子节点存放整行数据，二级索引的叶子节点存放主键值，因此二级索引查询可能需要回表。

explain 重点关注：type（访问类型，至少要 range）、key（实际使用的索引）、rows（扫描行数）、Extra（是否 Using filesort / Using temporary）。

最左前缀原则：联合索引 (a, b, c) 只能被 a、a+b、a+b+c 这样的查询条件使用，范围查询之后的列无法继续使用索引。

事务隔离级别：读未提交、读已提交、可重复读（MySQL 默认）、串行化。
可重复读通过 MVCC 实现，配合间隙锁可以解决大部分幻读问题。

## 五、Redis

常用数据结构：String、Hash、List、Set、ZSet。
缓存穿透的解决方案是布隆过滤器或缓存空值；缓存击穿用互斥锁或逻辑过期；缓存雪崩通过过期时间加随机值来避免。

Redis 持久化有 RDB（快照，恢复快但可能丢数据）和 AOF（追加日志，数据安全但文件大）。
生产环境常用两者结合：RDB 做冷备，AOF 保证数据完整性。

## 六、场景题

如何在保证性能的同时避免缓存与数据库不一致？
推荐"先更新数据库，再删除缓存"（Cache Aside），并配合延迟双删或订阅 binlog 异步删除，
以覆盖并发读导致的脏数据回填问题。对于强一致要求高的场景，应直接读库或使用分布式锁。

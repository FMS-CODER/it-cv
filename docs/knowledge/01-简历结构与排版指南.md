# 简历结构与排版指南

## 一、篇幅与整体原则

应届生简历以 1 页为佳；有 1-3 年经验的社招可以 1-2 页；超过 3 年且项目较多时最多 2 页。
简历的本质是"用最少的篇幅证明你能胜任目标岗位"，因此每一个字都要服务于"匹配度"。

三条基本原则：
1. 一页之内讲清楚"我是谁、我会什么、我做过什么"；
2. 与目标岗位无关的经历大胆删掉，不要为了凑数而堆砌；
3. 所有描述尽量可验证、可量化，避免空话套话。

## 二、顶部基本信息

顶部区域控制在 3-4 行，包含以下要素：
- 姓名（可加粗放大）
- 求职意向（必须写，且与投递岗位一致）
- 手机号、邮箱（邮箱建议用 姓名拼音@普通邮箱，避免花哨昵称）
- 城市（是否接受异地可注明）
- GitHub / 技术博客 / 个人站点（有则写，无则省略）

不要写的内容：性别、年龄、民族、政治面貌、家庭住址、身份证号、照片（除非岗位明确要求）。
这些信息既占篇幅，又可能带来不必要的偏见。

## 三、模块顺序与取舍

推荐顺序（按重要性从高到低）：
1. 教育背景：学校、专业、学历、起止时间、GPA（排名前 30% 才写）、核心课程（可选）
2. 技术栈：分层次列出，语言与基础 → 框架 → 中间件 → 数据库 → 工程化
3. 项目经验：最重要的模块，占整页 50% 以上篇幅
4. 实习/工作经历：有则放在项目经验之前或之后，按含金量排序
5. 荣誉奖项 / 竞赛：只写有分量的（省级以上、有排名）
6. 自我评价：可写可不写，若写则避免"吃苦耐劳、团队精神"这类无信息量的词

## 四、技术栈怎么写

技术栈最容易犯的错误是把名词堆成一片。正确做法是分层：
- 语言与基础：Java、JVM、并发编程、集合源码
- 框架：Spring Boot、Spring Cloud、MyBatis-Plus
- 中间件：Redis、RabbitMQ、Kafka
- 数据库：MySQL（索引、事务、SQL 优化）、PostgreSQL
- 工程化：Git、Maven、Docker、Linux

并且要用"熟悉 / 掌握 / 了解"体现掌握程度。原则是：写在简历上的每一条都必须能被追问三层以上，否则就是给自己挖坑。

## 五、排版细节

- 字体统一（中文宋体或思源黑体，英文 Times New Roman 或 Arial），字号 10-11pt；
- 行距 1.15-1.3，段前段后留白，不要挤成一片；
- 用项目符号（•）而不是长段落，每条控制在 1-2 行；
- 时间格式统一为"2024.03 - 2024.09"，不要混用"2024年3月"和"03/2024"；
- 对齐方式统一，标题加粗，正文不加粗；
- 导出为 PDF，不要发送 Word 或图片格式（排版会错乱）。

## 六、常见错误清单

1. 写了大量与岗位无关的校园经历（如"学生会干事""志愿者"），占用宝贵篇幅；
2. 项目描述只有"使用了 XX 技术"，没有"解决了什么问题、达到什么效果"；
3. 技能栏写了"精通 Java"，被追问 JVM 调优细节时答不上来；
4. 邮箱名很随意（如 xiaoshuaige123@），显得不专业；
5. 简历文件名写"简历.pdf"或"新建文档.pdf"，应命名为"姓名-岗位-学校.pdf"；
6. 出现错别字、中英文标点混用、格式不统一——这些细节直接反映严谨程度。
